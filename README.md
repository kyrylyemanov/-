# Тестування з використанням бібліотеки pytest

## Звіт до роботи

### Тема

Тестування програм за допомогою бібліотеки `pytest`.

### Мета роботи

Навчитися створювати й запускати тести `pytest`, перевіряти помилки та повторно використовувати тестові дані через параметризацію і fixtures.

---

### Виконання роботи

У [app.py](app.py) створено клас `Figure`. Він приймає квадрат, прямокутник або трикутник і додатну довжину. Невідомий тип фігури та нульова або від'ємна довжина спричиняють `ValueError`.

У [test_app.py](test_app.py) тести записано звичайними функціями з `assert`. За допомогою `pytest.mark.parametrize` перевіряються всі дозволені типи фігур, кілька неправильних типів і різні недопустимі значення довжини. Fixture `square` створює квадрат із довжиною 10. Fixture `allowed_figures` має область дії `module` і використовується у двох тестах. До двох тестів додано маркер `unit`; його опис налаштовано в [pyproject.toml](pyproject.toml).

#### Встановлення та запуск

У PowerShell створіть віртуальне середовище, активуйте його та встановіть pytest:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

Після встановлення з цієї папки запустіть тести:

```powershell
pytest -v
pytest test_app.py::test_allowed_figure -v
pytest -m unit -v
```

Для пошуку першої помилки з коротким traceback використовується команда:

```powershell
pytest -x --tb=short
```

#### Результати

Повний запуск `pytest -v` завершився результатом `12 passed`. Запуск одного параметризованого тесту завершився результатом `3 passed`, а команда `pytest -m unit -v` відібрала чотири позначені перевірки: `4 passed, 8 deselected`.

Щоб перевірити команду пошуку помилок, я тимчасово додав тест з навмисно хибною умовою `assert 1 == 2` і запустив `pytest -x --tb=short`. Pytest показав `FAILED` та рядок із хибним твердженням, після чого зупинився: `stopping after 1 failures`. Тимчасовий тест видалено, тому у фінальній версії всі тести проходять.

Різниця між підходами: `unittest.TestCase` організовує перевірки методами класу й надає власні методи на кшталт `assertEqual`; pytest дозволяє писати тести звичайними функціями з простим `assert`, а також має зручні параметризацію та fixtures.

Скріншоти для цієї консольної роботи не потрібні: результат запуску тестів відображається в терміналі.

### Висновок

- **Що зроблено:** створено клас `Figure`, параметризовані тести, fixtures і маркер `unit`.
- **Чи досягнуто мети:** так, тести написано й організовано за допомогою pytest.
- **Що нового дізнався:** навчився використовувати `pytest.raises`, `parametrize`, fixtures з областю дії `module` і маркери.
- **Чи відповів на запитання з роботи:** так, у звіті пояснено запуск pytest, різницю з `unittest` і наведено приклади параметризації, fixtures та маркерів.
- **Чи виконано завдання:** так, додано перевірки дозволених фігур, неправильних типів і довжин.
- **Чи виникли складнощі:** складнощів із запуском тестів не виникло; неправильні значення обробляються через `ValueError`.
- **Відгук про формат:** мені сподобалося, що параметризація дозволяє перевірити кілька наборів даних однією функцією.
- **Побажання:** надалі можна додати тести для інших класів і навчитися запускати окремі групи тестів у більшому проєкті.
